# Claude Design에 전달할 화면 범위

2026-09-30 사용자 결정: 디자인은 Claude Design, 기능과 API 연동은 Codex가 담당한다.
기존 기능 확인 화면은 최종 디자인의 기준이 아니다.

## 제품과 사용자

메뉴를 관리하는 사람이 메뉴 이름·가격·분류·주문 가능 여부를 확인하고 등록·수정·삭제하는 한국어 웹 앱.
한 서비스의 여러 화면이 같은 디자인 토큰과 같은 컴포넌트 규칙을 사용하게 한다.

## 화면과 이동

| 화면 | React 주소 | 행동과 내용 |
|---|---|---|
| 메뉴 목록 | /?page=1&q=&category=&price= | 이름 검색, 하위 카테고리, 기준 가격 초과, 카드 목록, 페이지 이동, 등록으로 이동 |
| 메뉴 상세 | /menus/:menuCode | 이름·가격·분류·주문 상태·번호, 수정으로 이동, 삭제 확인 |
| 메뉴 등록 | /menus/new | 이름·가격·카테고리·주문 상태 입력, 저장, 취소 |
| 메뉴 수정 | /menus/:menuCode/edit | 등록과 같은 폼에 기존 값을 채움, 저장, 취소 |

목록 → 상세 → 수정 → 저장 → 상세.
목록 → 등록 → 저장 → 상세.
상세 → 삭제 확인(취소 가능) → 삭제 성공 → 목록.
검색·페이지 조건은 URL에 있어 새로고침과 뒤로가기에 유지된다.

## 디자인할 상태

- 목록 로딩, 검색 결과 없음, 등록된 메뉴 없음, 서버 연결 실패와 다시 시도.
- 상세 404와 목록으로 이동.
- 이름·가격·카테고리별 입력 오류, 저장 중 버튼 비활성, 저장 실패, 저장 성공 알림.
- 삭제 확인 다이얼로그와 삭제 실패.
- 주문 가능/불가 배지는 글자로도 구분.
- 데스크톱과 모바일에서 같은 기능에 접근 가능.

## 실제 제공 데이터

menuName, menuPrice, categoryName, orderableStatus, menuCode.
서버에는 메뉴 이미지·설명·별점·재고·매출·판매 통계 필드가 없다.
이를 실제 기능처럼 추가하지 않는다. 메뉴 카드는 위 필드로 구성한다.

현재 과제 DB의 예시 메뉴: 소고기 비빔밥 11,000원 / 한식 / 주문 가능,
아메리카노 4,500원 / 커피 / 주문 가능,
초콜릿 브라우니 5,500원 / 베이커리 / 주문 불가.
디자인 예시 데이터이며 실제 매장 데이터는 아니다.

## 기준 파일

첨부 montage.tokens.json이 토큰 기준이고 tokens.css는 그 파일을 변환한 결과.
색은 semantic 토큰, 타이포는 .title1·.heading2·.body1·.label1·.caption1 등,
간격은 --space-*, 모서리는 --radius-*로 표현한다.
API의 정확한 입력·응답은 api-docs.json과 프로젝트 docs/api-contract.md를 따른다.
