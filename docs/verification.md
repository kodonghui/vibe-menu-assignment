## 최종 앱 검사 · 2026-09-30

- 환경: 로컬 Windows 11 / PowerShell / Java 17.0.20 / Node.js 24.18.0 / npm 11.16.0 / Gradle 9.7.1.
- backend: Gradle test bootJar 성공. 독립 H2 메모리 DB의 JPA CRUD·잘못된 카테고리·가격 초과 경계 3개 테스트 통과.
- frontend: npm run lint, npm run build 통과. Vite 8.3.1.
- 토큰: semantic 색+그림자 74개(두 테마), 간격·z-index·radius·opacity 합계 52개, 타입 19종.
- 원본 style.ts에서 radius 상수 16종을 보충하고 실제 CSS 참조 누락/하드코딩 색/글자 크기 없음 확인.
- 실행 서버: 8090, dev H2 파일 DB. React: 5175.
- API: 목록·페이징·정렬·카테고리·등록·상세·수정·가격 초과·400/404·삭제·CORS 허용/차단·Swagger 확인.
- OpenAPI: 실행 서버에서 10개 연산의 명세를 저장. 전달용 토큰·CSS·명세 사본 갱신.
- 브라우저: 페이지 이동, 이름 검색, 새로고침 시 조건 유지, 필수값 오류, 등록→상세, 기존 값 수정 폼, 수정→상세, 삭제 확인/취소/완료→목록 확인.
- 브라우저 검사 메뉴는 정리되어 초기 예시 메뉴 16개가 유지됨.

## Claude 디자인 적용 후 브라우저 확인

- 공통 헤더·카드·상세·등록/수정 폼·상태·삭제 확인을 원본 JSX/CSS Module로 구현. 캔버스 런타임이나 보드 전용 CSS는 앱에서 실행하지 않음.
- 적용 후 tokens/lint/build 및 root check-tokens 통과. runtime 라이브러리 추가 없음. CSS Module 클래스 참조 누락 0.
- 전체 16개, 첫 페이지 12개와 둘째 페이지 4개 확인. 둘째 페이지에 있는 소고기 비빔밥을 이름 검색으로 찾음.
- 이름 라떼 + 커피 + 5000원 초과 → 바닐라 라떼 5500원만 표시. 새로고침 후 세 입력값과 결과 유지.
- 필터 결과는 존재하지만 범위를 벗어난 page=2일 때 별도 안내와 조건을 유지한 첫 페이지 복구 확인. 실제 빈 검색과 구분됨.
- 필수값이 비었을 때 오류 3개와 메뉴 이름의 첫 오류 포커스 확인. 식사/음료/디저트 optgroup와 Y/N 라디오 확인.
- 임시 메뉴 20 등록 → 상세, 기존 값 수정 폼 → 0원·주문 가능 수정 → 상세 확인. 이 메뉴만 사용하여 검사함.
- 느린 PUT에서 입력·라디오·선택·저장·폼 취소 잠금 확인. 저장 중 헤더로 목록을 선택하면 응답 후에도 목록 유지, 실제 수정 결과는 목록에 반영됨.
- 삭제 대화창 초기 취소 포커스, Tab/Shift+Tab 순환, Escape 취소와 삭제 버튼 포커스 복귀 확인. 취소 후 메뉴 유지.
- 느린 DELETE에서 취소·확인 모두 잠금, Escape로 닫히지 않음, 성공 후 목록으로 복귀 확인. 임시 메뉴 정리 후 전체 16개 확인.
- 존재하지 않는 메뉴의 404 전용 안내와 목록 복구, 0개 검색의 빈 결과 안내 확인.
- 검사 탭에만 일시적으로 통신 실패를 적용해 오류 안내 → 통신 복구 → 같은 검색 조건 재시도를 확인함. 서버는 중단하지 않았으며 통신 설정을 복원함.
- 라이트/다크 전환 시 배경·글자 색과 버튼 명칭 변경 확인. 모바일 폼의 입력·선택·라디오·버튼이 겹치지 않음.
- 390×844 / 800×900 / 1280×900 뷰포트에서 카드 1/2/3열. 각 문서 scrollWidth=clientWidth로 가로 넘침 없음. 검증 후 임시 뷰포트를 해제함.
